# Интеграция Hermes Agent с XMPP

## Цель

Установить Hermes Agent на Ubuntu 24.04 рядом с работающим ejabberd и подключить его к XMPP как `hermes@aversa.run`. Бот обслуживает личные сообщения и приватные MUC-комнаты, сохраняя штатные сессии, память и инструменты Hermes.

## Архитектура

Hermes работает на хосте VPS под отдельным системным пользователем и запускается через systemd. ejabberd продолжает работать в Docker. XMPP интегрируется как сторонний platform plugin Hermes, без изменения исходников Hermes и без публичного HTTP API.

Плагин устанавливает TLS-соединение с ejabberd как обычный XMPP-клиент. Входящие сообщения преобразуются в штатные `MessageEvent` Hermes, а ответы отправляются через адаптер обратно в личный чат или MUC.

## Модель и провайдер

- OpenAI-совместимый API: `https://api.aitunnel.ru/v1`.
- Модель: `gpt-5.6-sol`.
- API-ключ хранится только в закрытом env-файле Hermes.
- Секреты не помещаются в исходники, журналы или документацию.

## XMPP-идентификация

- Аккаунт бота: `hermes@aversa.run`.
- Ресурс клиента: `Hermes`.
- Подключение только с проверкой сертификата TLS.
- Сообщения от собственного JID и других ресурсов бота игнорируются для защиты от циклов.

## Авторизация

Разрешённые пользователи:

- `admin@aversa.run`
- `yuklya@aversa.run`
- `julia@aversa.run`

Сравнение выполняется по нормализованному bare JID. Сообщения остальных пользователей не передаются агенту и не получают содержательного ответа.

## Личные сообщения

- Бот отвечает на каждое непустое текстовое сообщение разрешённого пользователя.
- Контекст изолирован по bare JID пользователя.
- Сообщения без текста и неподдерживаемые вложения на первом этапе игнорируются.

## Приватные комнаты

- Плагин принимает прямые и mediated MUC-приглашения только от разрешённого пользователя.
- После принятия bare JID комнаты сохраняется в локальном persistent state плагина.
- Список комнат переживает перезапуск службы.
- Плагин автоматически входит в сохранённые комнаты после переподключения.
- В комнате агент запускается только при обращении: упоминании `Hermes`, упоминании полного JID бота, обращении вида `Hermes, ...` или ответе на сообщение бота, если клиент передаёт reply metadata.
- Перед передачей агенту маркер обращения удаляется из текста.
- Активировать бота в комнате может только разрешённый пользователь.
- Контекст изолирован по паре `room bare JID + sender bare JID`.
- Ник бота при конфликте получает безопасный суффикс, но распознавание обращений продолжает учитывать фактический ник.

## Безопасность выполнения

- Hermes запускается без root под отдельным системным пользователем.
- Рабочие файлы доступны только этому пользователю.
- Env-файл имеет права `0600`.
- Инструменты терминала Hermes используют Docker backend или другой штатный sandbox, а не прямое выполнение от пользователя хоста.
- Hermes API, если он понадобится для диагностики, слушает только `127.0.0.1` и защищён bearer-ключом.
- В журналы не выводятся пароли, API-ключи и полное содержимое приватных сообщений.

## Надёжность

- systemd автоматически перезапускает Hermes после сбоя.
- XMPP-клиент восстанавливает соединение с ограниченной экспоненциальной задержкой.
- Одно входящее сообщение обрабатывается один раз по stanza/message ID с кратковременным дедупликационным кэшем.
- Длинные ответы разбиваются на XMPP-сообщения по безопасной границе.
- Ошибка модели возвращает пользователю короткое нейтральное уведомление и записывается в журнал без секретов.
- Одновременные запросы внутри одной сессии выполняются последовательно; независимые сессии могут работать параллельно в пределах лимита Hermes.

## Конфигурация плагина

Плагин читает из env-файла JID и пароль бота, адрес и порт XMPP, разрешённые JID, путь к persistent state, ник бота и политику упоминаний. Секреты не дублируются в `config.yaml`; там могут храниться только несекретные настройки платформы `xmpp`.

## Границы первого этапа

Не входят: OMEMO, голос, файлы, автоматическое присоединение без приглашения, ответы на все сообщения комнаты, команды администрирования ejabberd и публикация Hermes API в интернет.

## Проверка

1. Разрешённый пользователь получает ответ в личке.
2. Запрещённый пользователь не запускает агента.
3. Приглашение разрешённого пользователя добавляет приватную комнату.
4. Приглашение запрещённого пользователя отклоняется.
5. Обычный текст в комнате игнорируется.
6. Обращение разрешённого пользователя запускает агента.
7. Обращение запрещённого пользователя игнорируется.
8. После перезапуска служба входит в сохранённую комнату.
9. Два пользователя одной комнаты получают независимые контексты.
10. Секреты отсутствуют в `journalctl` и файлах проекта.

## Развёртывание и откат

Установка выполняется поэтапно: системный пользователь, Hermes, провайдер модели, XMPP-аккаунт, плагин, sandbox и systemd. Перед включением автозапуска выполняется ручной smoke test.

Для отката достаточно остановить и отключить systemd-службу Hermes. ejabberd и существующие XMPP-клиенты при этом не изменяются. Аккаунт бота можно оставить выключенным или удалить отдельной административной командой.
