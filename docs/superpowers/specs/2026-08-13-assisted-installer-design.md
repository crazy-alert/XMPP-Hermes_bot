# Интерактивное завершение установки Hermes XMPP

## Цель

Установщик доводит развёртывание до проверенного рабочего состояния с минимумом
ручных действий, но отдельно подтверждает системные изменения и запуск службы.

## Docker

- Поддерживаемый backend инструментов Hermes — Docker.
- Сначала проверяются Docker CLI, группа `docker` и доступность daemon.
- Если Docker отсутствует, до установки Hermes пользователь получает явное
  предложение установить пакет `docker.io` из репозиториев Ubuntu.
- Подтверждение принимает только `yes`, `y`, `да` или `д` без учёта регистра.
  Отказ, EOF и неинтерактивный stdin завершают работу без дальнейших изменений.
- После согласия выполняются `apt-get update`, установка `docker.io`,
  `systemctl enable --now docker` и повторная проверка CLI, группы и daemon.
- Установленный Docker не удаляется при более позднем откате Hermes: автоматическое
  удаление общего системного компонента небезопасно.

## Установка и проверки

Существующие проверки Ubuntu, путей, владельцев, типов файлов и pinned Hermes
сохраняются. Установщик создаёт системного пользователя `hermes`, защищённые
каталоги и env-файл, устанавливает pinned Hermes и зависимости XMPP, копирует
плагин по allowlist, проверяет unit через `systemd-analyze verify`, добавляет
`hermes` в группу `docker` и запускает `hermes doctor` без вывода секретов.

Обязательные XMPP-поля должны быть заполнены до предложения запуска службы.
Установщик не создаёт XMPP-аккаунт, не меняет ejabberd и не печатает пароль.

## Запуск службы

После успешной установки и проверок пользователь получает отдельный вопрос:
включить автозапуск и запустить Hermes сейчас. При согласии установщик проверяет,
что unit загружен, выполняет `systemctl enable --now hermes-gateway`, затем
подтверждает `is-enabled` и `is-active`. При отказе служба остаётся остановленной
и отключённой. Ошибка запуска завершает installer с ошибкой и безопасными
командами `systemctl status` и `journalctl`; секретные значения не выводятся.

## Проверка

Harness покрывает Docker уже установлен, отказ, согласие, неинтерактивный ввод,
ошибку установки/daemon; отказ и согласие на запуск; ошибку doctor/start и
проверку итогового active/enabled состояния. После focused RED/GREEN выполняются
весь deployment suite, `bash -n`, privacy scan и scoped security review.
